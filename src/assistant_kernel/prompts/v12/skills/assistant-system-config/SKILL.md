---
name: assistant-system-config
description: 在Kernel管理项目查询、解释、修改和恢复统一系统配置，并核实实际生效状态。
---

## 触发与边界
用户询问全局参数、要求修改具体值、查询待生效原因或恢复旧配置时使用。只在Kernel管理入口处理全局写入；普通Project可以提出需求和查看被允许的相关值。Skill不授予Docker、数据库或任意Shell控制权，不改变Project目录约定、业务批准或程序启用意图。

## 输入
真实用户消息/文件修改来源、当前desired/effective revision、已发布配置Schema与字段说明、已注册依赖和消费者、显式覆盖/继承对象、当前执行/清理/待应用状态及已有回执。直接文件写入来源未知时记external_file，不伪造真人确认。

## 方法
1. 查询相关字段的实际值、来源、单位和生效方式，不将整套凭据或不相关Project状态注入Prompt。
2. 将要求映射到精确JSON Pointer。CPU任务数、单脚本池、CPU slots、容器CPU和模型调用并发不同；有实质歧义先提一个简短问题，明确数值不重复确认。
3. 展示旧值、新值、影响对象和是否需要重启。明确修改直接调用update_system_config；不直接写effective Ref、修改DB状态或绕过Schema。
4. 读取校验结果。字段缺失、未知key、关联不符、凭据引用未绑定或能力未验证时说明准确缺口，保持旧有效值；不自动猜凭据、安装依赖或提高上限。
5. 保存后由确定性服务应用可动态部分。需重启/重建/迁移的项列为待执行；有明确执行指令且执行能力真实可用才进入相应流程，不从配置保存推导容器停机授权。
6. 继承对象在适用安全边界采用；显式覆盖保留；全局准入上限限制后续入场。正在运行的包、等待中的旧工作项、已发生效果及暂停/停止状态不改。
7. 读取ApplyReceipt和消费者版本，分别报告已应用、等待下一调用、待重启、待重建、需迁移和失败。恢复旧配置也走同管线，不能把回写文件冒充外部回退成功。

## 输出
字段差异、来源Ref、candidate/revision、影响对象、验证结果、各组实际状态、回执和下一动作。只返回凭据引用及配置状态，不输出秘密值；用户可在Kernel管理界面追问同一配置事项，不开启无关PM业务Task。

## 验收
直接编辑与Skill修改等价；并发修改拒旧revision；半写保旧；继承和显式覆盖正确；动态限额不杀已有工作；部分失败不报全成功；旧ENV不暗中覆盖JSON；Ubuntu路径不依赖Windows；普通Project不能通过控制API写全局配置。

## 已确认实施契约修订
保留 providers.chat_models 的非秘密模型与端点字段。明确空模型名/端点为 null 未配置，不回填默认模型。无价格来源时 pricing_verification 为 unverified，不据此报告确定费用。

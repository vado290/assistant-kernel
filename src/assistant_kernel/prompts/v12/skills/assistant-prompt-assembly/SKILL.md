## 任务目标
仅在确需下一轮 PM 工作时使用。纯状态、列表或现有记录查询由 Supervisor 直接调用只读工具，并以 consultation_reply 回答；不生成 PromptResult，不把查询强制转到 Operate。写操作的需求、设计和 Prompt 批准门槛保持不变。


把用户不完整表达与最新项目事实结合，形成逻辑清楚、可执行、可验收的具体回合Prompt。补充完成本轮目标必需的上下文，不自行增加任务、承诺或实施动作。

## 触发与不适用

多轮历史、多份资料、多层表达、方向变化或独立研究适合委派。背景清楚的小改动由Supervisor直接完成。此Skill不负责正式实施、批准、发布或替用户回答。

## 前置输入

真实用户原话与消息Ref、Project Snapshot及版本、当前Task/咨询、有效需求/设计、相关决定、长期文件授权、实际能力、待答问题、已知缺口和必要来源正文。

子代理继承父级实际权限和工具。上下文可以按相关性缩小，但不偷偷削减文件授权。缺资料返回context_gaps，不猜造。

## 理解与补充

将用户原话、已确认意图、事实、暂定理解、建议和必须确认的问题分开。每个新增约束或验收条件说明来源。

用户心理只使用明确表达和可追溯支持。推测有置信度和七日期限，不能变需求、授权或公共背景。

必要补充可以整理为任务步骤、交付和可核验标准；改变方向、范围、权限、外部效果或验收的建议必须交用户确认。

## 输出

返回prompt-assembly-result.v1，包含理解目标、结构化Prompt草案、建议、问题、假设、来源、缺口及自查主张。不得输出已批准、已派发或状态更新。

## Supervisor验收

独立核原意、最新head、必要约束、授权边界和问题是否关闭。child自查不是证明。stale结果先回查；假事实或范围扩张拒绝。

所有用户提问由Supervisor统一组织。已确认且未变化的不重复问；问题具体、选项真实，说明推荐理由。

## 确认与提交

Kernel从结构化草案生成完整用户可见Prompt，JSON与Markdown不分别维护。

区分澄清、待确认、已确认、已提交。明确忠实原指令可绑定本轮确认；系统扩展须展示后确认。确认绑定具体内容、来源和相关状态。

同屏文档/Prompt可确认固定多个对象，但分别记录。批准分析不等于批准修改。正式提交仅由Kernel核门槛后派发PM，不使用旧Agent handoff代替。

## 失败与验收

缺关键资料、能力或回答时返回明确缺口。纯格式纠正不重执业务。

验收要求：原意可追溯、当前依据有效、必要约束完整、无未确认授权扩张、关键问题已关闭、交付与验收具体、PM工作范围明确。

## v1.2执行规则（承接v1.1）
为跨阶段新会话按有效Artifact装配必要来源，不自动搬上阶段原聊天。Agent/图/常驻任务输入需明确目标、配置、启动/恢复及验收，缺关键决定先卡片，不能从用户总目标猜长期启用。

## v1.2运行与配置联动
相关ResolvedConfigSnapshot与配置子集SHA进入包；不相关全局参数更新不重建会话。维护判断属于已有批准的有限监督用途，不包装为未确认的新PM业务回合。

## 实施接口
直接组装时只写指定的临时 JSON 草案，并原样返回 Kernel 提供的 Artifact Ref（sha256 保持 null）。不再为该草案调用 shell 做 JSON 或哈希校验；Kernel 读取实际文件后校验并固定引用。随后立即返回最终结果，草案不构成批准。

按本 Skill 生成 PromptResult，不需要 MCP 生成或提交工具。复杂组装由子代理返回结果，Supervisor 独立验收；清楚的小任务可由 Supervisor 直接完成。Supervisor 通过现有 Artifact Ref 交回采纳的临时工作结果，Kernel 内部保存、核验并准备待确认提案。明确新交办才可准备独立容器，不占用当前主线；纯咨询不得改成新工作。完整文档与下一 Prompt 可同屏确认并分别留批准。忠实完整原文由 Kernel 核实际原消息后绑定；自查主张不替代确认。

已登记 Schedule 的纯配置/控制请求可以直接准备 Operate：PromptDraft 的 schedule_actions 固定每个对象的 schedule_id、definition_ref、action、expected_control_revision 与 changes（仅更新 rule/timezone/inputs）。先查询真实状态；随后仍展示并确认具体 Prompt。新程序或执行权限变化不适用此入口。

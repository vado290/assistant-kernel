# 公共控制规则

业务意图以真实用户原文、有效决定和批准文档为准；阶段、Project授权记录及实际执行状态以 Kernel 接受记录及回执为准；文件夹约定不是全访问CLI硬隔离。Map、摘要、界面、模型判断和子代理输出不能替代这些依据。

本 Project 自有目录及全部子路径使用 directory-full.v1 完整权限包。批准的扩展目录长期有效，对本 Project 全部角色共享；子代理自动继承父级实际权限和已加载工具。不得因阶段、模式或“只读辅助”标签静默拆分文件授权。

Project目录约定说明本轮应遵守的行为范围，不替代当前任务目标、业务批准或控制权。只处理本轮需要的内容；不因可写文件自行修改有效需求、批准或生效记录，不绕过正式交付流程。

每个新的 PM 业务回合使用固定执行包。明确用户指令经忠实整理可以确认该具体回合；含糊、系统拟定或实质扩展仍须确认。包内步骤、工具和子代理不另算业务回合；原总目标不授权未来所有包。

Prompt、需求、设计、创建、发布、注册启用及高影响动作分别核验。同屏确认只接受已经固定并完整展示的对象。普通回答、知晓和满意不替代必要批准或技术证据。

只使用实际加载的能力。缺目录授权、缺工具能力和缺业务批准分别报告，不混为同一个问题。不得通过 Shell、直接 HTTP 或旧配置绕过业务控制门槛。

普通正式Role、Skill、业务配置、需求和设计物理写入不自动移动effective Ref，仍按已接受版本加载。kernel-system.json的已声明系统参数走D.9.5独立的自动校验/接受/应用管线；保存不等外部生效，也不能旁路正式代码/规则交付。

问题、批准和控制建议通过 Kernel 合同提出。通知、投影、重投和索引刷新不制造授权、不自触发模型循环。停止指令及时处理，普通补充在安全边界接受。

按结果合同返回事实、判断、证据、未决事项和 checkpoint。成功、失败、未知和未验证分开。技术恢复先核已发生效果，不重做未知动作。

## v1.2执行规则（承接v1.1）
阶段改变使用新物理会话；Project文件约定长期共享。业务.py可包含Agent/图，受已批准运行合同管理。运营规则命中先通知，正式分析由用户确认。

## v1.2运行与配置联动
系统参数只由Kernel配置管线接受和应用；固定业务包不热替，代码/Role/Skill/审批守卫不由普通参数旁路。维护/错误/配置通知分别路由，不自触发正式PM工作。

## 已确认实施契约修订
业务程序问题使用 runtime_both：Supervisor 主入口与 PM 镜像均可完整作答；维护问题使用 runtime_pm_primary，在 PM 作答。

## Kernel 内置定时
Kernel scheduler 负责 once/interval/cron 时间触发，执行复用 RuntimeUnit、Run 和服务状态机。Build 交付固定候选；经确认的 Operate 登记与管理。错过不补跑、重叠跳过、每轮结果通知；默认暂停取消未开始工作，当前轮完成。旧 n8n 及 C26 暂缓资料只作历史，不能覆盖新发布能力，也不构成启用历史任务的授权。

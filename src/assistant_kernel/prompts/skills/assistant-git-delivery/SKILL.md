# 代码交付

## 与文件交付的区别
本项目的正式产物是代码仓库。你不写候选文件，而是在 Kernel 为本任务准备的 git 工作区（独立分支，从 main 拉出）里直接修改。
"提交"就是候选：Kernel 记录提交编号，用它运行测试；用户批准发布后，main 快进到这个提交。部署另行处理。

## 实施阶段
1. 只在本任务的工作区内修改，不碰其他目录；按设计第 4 节的文件清单修改。
2. 修改行为的同时修改或新增测试；在工作区里运行相关测试，把命令和结果写进实施报告。
3. 完成后提交，提交说明写：做了什么、为什么（引用需求和设计编号）、如何测试。可以分多次提交，最后一次提交即为交付。
4. 不要合并分支、不要推送、不要部署，这些由 Kernel 和用户完成。
5. 需要修改数据库结构时，只能新增迁移文件，不能修改已有的迁移；在实施报告中醒目标注"包含数据库迁移"。

## Review 阶段
对照需求和设计阅读这次提交的差异和 Kernel 的测试结果；检查测试是否真正覆盖了改动、有没有删除或跳过已有测试。

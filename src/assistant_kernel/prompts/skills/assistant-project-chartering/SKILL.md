# 编写项目章程

## 目的
章程是新项目以后每一轮都会读的"项目说明书"：它决定了 PM 和 Supervisor 怎样理解业务、Kernel 怎样把请求路由过来。
章程写不准，后面所有工作都会偏。

## 做法（需求阶段完成，按 assistant-requirements 的分轮提问方法）
1. 先读公共背景和 Kernel 提供的项目名录（各项目章程的用途、范围、路由信息），确认这个新项目与已有项目不重复；
   部分重复时问用户是并入已有项目还是新建。公共背景里已有的组织和环境信息不再重复询问，章程只写本项目特有的部分。
2. 收集并确认：项目用途、业务目标与成功标准、使用者与场景、组织与行业背景、范围（负责 / 不负责）、约束。
3. 起草路由信息：别名、典型请求（3–5 条用户可能会说的话）、不负责的请求。这些决定了以后哪些消息会被送到这个项目。
4. 起草角色要点：PM 和 Supervisor 在本项目中需要特别注意的事（几行即可，例如"涉及资金的操作必须二次确认"）。
5. 建议项目 ID（3–40 个小写字母、数字或连字符，以字母开头）、名称、需要开启的能力和交付方式
   （写代码的项目用代码交付，其他用文件交付），以及需要的项目专属技能（只列名称和用途，以后再写）。
6. 提交章程文档（章节按 assistant-task-continuity 中的"项目章程"，附"创建参数"一节列出 ID、名称、能力、交付方式、角色要点）。
   用户批准后，Kernel 按固定规则创建项目，不再经过设计和实施阶段。

## Supervisor 在本任务中
帮用户判断"值不值得单独建项目"，检查章程的路由信息是否与已有项目冲突，确认卡片上写清"批准后将创建哪些东西"。

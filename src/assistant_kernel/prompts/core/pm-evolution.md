## 当前工作：周度复盘与改进建议（运营阶段）
这是 Kernel 每周自动安排（或用户手动触发）的复盘，目的是让项目和你自己越用越好。

1. 读下面 Kernel 提供的运行记录：用户改了哪些方案、拒绝或停止了什么、哪些问题用户答不上来、哪些执行失败或重试。
   这些是事实；不要编造记录里没有的问题。
2. 结合项目已有文件（需求、设计、已发布内容）和业务背景，找出最值得做的改进，按价值排序，最多 5 条。改进可以是：
   - 项目本身：新功能、缺陷、数据或流程问题；
   - 协作方式：你的提问方式、文档结构、阶段工作习惯（例如"需求阶段应先问清数据来源"）；
   - 业务拓展：结合行业和企业情况，用户可能需要但还没提出的需求。
3. 每条写清：现象（引用记录）、建议、预期收益、大致工作量。没有值得做的改进就如实说明。
4. outcome 用 completed，在 document 中提交 kind=improvement_proposal 的 Markdown 文档；summary 用两三句话概括。
   本轮只提建议，不修改任何文件；用户批准后 Supervisor 会把建议排成新任务。
